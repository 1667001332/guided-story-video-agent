# v0.7.0 — V2 执行运行时与 Provider 合约

本版本在 v0.6.0 的内容驱动视频任务链路上，引入可恢复、可审计的 V2 执行层。

- 建立 `MoviePlan → FilmIR → MovieIR → VideoJob → ExecutionPlan → ExecutionBundle → ExecutionRuntime` 主链，明确创作、编译和执行边界。
- 增加 MoviePlan、FilmIR、MovieIR、VideoJob、ExecutionPlan 和 ExecutionBundle 的结构化契约、版本、指纹与来源血缘信息。
- 增加执行状态机、事件记录、检查点、运行时状态存储、租约和可恢复执行，支持在中断后继续处理未完成单元。
- 增加 Provider 能力快照、提交/轮询/取消/下载/验证契约、幂等键、错误归一化和敏感信息清理。
- 增加 Fake/Mock Provider Runtime 与 HTTP 传输层，支持不调用真实 API 的执行链路验证。
- 增加统一 Failure Protocol：结构化失败报告、安全重试、`SUBMISSION_UNCERTAIN` 停止告警、
  Policy/Capability RevisionRequest、敏感信息清理和失败事件审计。
- 保留不可变 RevisionCandidate、RevisionDiff、RevisionGuard 与显式 Apply 边界；Apply 后
  旧下游产物 stale，新的 ExecutionBundle 必须重新编译并拥有新的 fingerprint。
- 保留旧版 Session、Storyboard 和 Agnes 渲染兼容边界；旧会话继续只读迁移，V2 兼容包装器保留并标记弃用。
- 将 Session 持久化 schema 升级到 7，同时覆盖旧 schema 的读取兼容测试。

## 验收边界

本版本的离线执行、状态持久化、Provider 合约和兼容性测试不等同于真实文本模型或付费视频 Provider 已成功调用。真实 API 验收仍需使用测试者自己的密钥，并按[师兄 API 测试指南](../mentor-testing-guide.md)分阶段执行。

`SUBMISSION_UNCERTAIN` 不会自动重新提交；必须先人工核对 Provider 后台。V2 Fake/Mock Runtime
也不等同于真实 Provider 成功。
