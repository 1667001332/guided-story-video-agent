# v1.0.0 — Bounded and Auditable V2 Runtime

`v1.0.0` 将 V2 执行运行时作为首个稳定发布边界：创作、编译、Provider 执行和失败恢复
各自保持明确的责任范围，离线验证结果不会被表述为真实 Provider 或付费视频调用成功。

## 发布内容

- 固化 `MoviePlan → FilmIR → MovieIR → VideoJob → ExecutionPlan → ExecutionBundle → ExecutionRuntime` 主链及来源指纹。
- 提供统一 Provider Failure Protocol，将失败路由为 `RETRY`、`STOP_AND_WARN`、`REQUEST_REVISION` 或 `ABORT`。
- 对提交超时和 `SUBMISSION_UNCERTAIN` fail-closed：持久化提交意图与 checkpoint，禁止自动重新提交。
- 对 Policy/Capability 失败生成经过清洗的 Revision Request；必须经过 RevisionCandidate、RevisionDiff、RevisionGuard 和显式 Apply。
- Apply 后旧下游产物标记 stale，并通过显式重编译边界生成新的 ExecutionBundle 和 ExecutionRun。
- 保留 Fake/Mock Runtime、旧版 Session/Storyboard/Agnes 兼容边界和离线测试能力。

## 验收边界

本发布包含离线状态机、持久化、事件审计、敏感信息清洗和 Provider 合约验证；这些结果
不等同于真实文本模型、真实视频 Provider、付费接口鉴权或视频质量验收成功。真实 API
验收必须使用测试者自己的密钥，并遵循[师兄 API 测试指南](../mentor-testing-guide.md)。

`SUBMISSION_UNCERTAIN` 必须先由人工核对 Provider 后台，不能通过 resume 或 retry 自动
补交；真实 Provider 的发布与付费测试仍是独立的运行阶段。
